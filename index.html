sql
SQL for Product Analytics
6 weeks · ~42 hours  ·  Weeks 3–8
Why SQL is the first skill to crackAlmost every PM interview at a funded Indian startup includes a SQL round. It's the clearest signal you can work with data independently. At beginner level, you need 6 weeks to reach interview-ready. Don't rush this — window functions and retention queries at the end are what separate PM candidates.

Week-by-week

Week 3SELECT, WHERE, ORDER BY, LIMIT, DISTINCT. 7 hrs. Do all of SQLZoo's SELECT basics (levels 0–4). Don't move on until these feel automatic.
Week 4GROUP BY, COUNT, SUM, AVG, HAVING. 7 hrs. HAVING vs WHERE is where most beginners get stuck — make sure this is clear before moving on.
Week 5JOINs — INNER, LEFT, RIGHT, FULL OUTER. 7 hrs. Draw Venn diagrams. Know when a LEFT JOIN vs INNER JOIN changes your result in a product context.
Week 6Subqueries and CTEs (WITH clause). 7 hrs. CTEs make complex queries readable. Interviewers love them — it signals you think in steps, which is a PM trait.
Week 7Window functions: RANK(), ROW_NUMBER(), LAG(), LEAD(), PARTITION BY. 8 hrs. Master PARTITION BY. These appear in almost every data-focused PM interview.
Week 8Product-specific queries. 6 hrs. Funnels (step-drop-off), DAU/MAU calculation, 7-day and 30-day rolling retention cohorts.

Product Fundamentals
6 weeks · ~42 hours  ·  Weeks 9–14
SQL gets you in the room. Product thinking keeps you there.By doing SQL first, you've already trained yourself to ask "how would I measure this?" — which is exactly the mindset you need while learning North Star metrics and KPI trees. You'll also build Portfolio Piece #1 here: a full PRD for the IDH platform.

Skills to build

PRD writing
Structure: context → problem → goals → non-goals → user stories → success metrics → open questions.
Prioritisation
RICE scoring, MoSCoW, Impact vs Effort. Know when to use each.
North Star + KPI trees
Every product has one North Star. Draw this tree for the HDFC dashboard — you already know the data.
User stories
"As a [field worker], I want [to log data offline], so that [entries aren't lost in low-connectivity zones]."
Product sense framework
Clarify → segment users → pain points → ideate → prioritise → define metrics. Practice this structure out loud.
A/B testing basics
Control vs variant, hypothesis definition, statistical significance in plain language. Tier 2 companies test this.

AI / LLM Knowledge for PMs
6 weeks · ~42 hours  ·  Weeks 15–20  ·  runs parallel with applications
This is the differentiator. You already have a head start.You build with Claude Code in production. Most PM candidates can describe AI features — you've shipped them. This phase gives you the vocabulary to talk about it. Almost none can spec an AI feature, discuss RAG vs fine-tuning tradeoffs, or define evaluation criteria for LLM output. That gap is where the 30–50% salary premium lives.

Skills in order

ML fundamentals (non-code)
Supervised vs unsupervised, classification, regression, clustering. You need vocabulary, not maths.
How LLMs work
Tokens, context windows, temperature, next-token prediction. Enough to know why the model behaves the way it does.
RAG vs fine-tuning
When to retrieve vs bake in knowledge. This is a product decision, not just engineering. You will be asked this in AI PM interviews.
Prompt engineering for products
How a product feature's system prompt becomes a spec. This is how you write AI PRDs that engineers can actually build from.
AI failure modes
Hallucination, bias, latency, cost, context limits. A PM's job is to account for failure before it ships. Know all five cold.
Evaluating AI product quality
Human eval, A/B testing with LLM judges, qualitative scoring. You define what "good" means so engineering can measure it.

Week-by-week

Week 15ML fundamentals. Complete "AI for Everyone" by Andrew Ng on Coursera (audit free, ~6 hours). Do it in one week.
Week 16LLMs. Watch Andrej Karpathy's "Intro to Large Language Models" on YouTube (1 hour). Then Cohere LLM University, first 3 modules. Also: send first job applications this week.
Week 17RAG and fine-tuning. Read 3 articles on RAG. Write a 200-word note: when would you use RAG vs fine-tuning for a health NGO data tool?
Week 18Prompt engineering for products. Read Anthropic's Prompt Engineering Guide. Write 3 system prompts for hypothetical features on the HDFC dashboard.
Week 19AI failure modes. Read 5 AI product post-mortems. For each: identify the failure, what a PM should have caught, how you'd spec a guard-rail.
Week 20Portfolio Piece #2. Write a 2-page AI Feature Spec for adding an AI assistant to the HDFC CSR dashboard. Architecture decision, system prompt, success metrics, failure risks, evaluation criteria.

Interview Prep + Active Applications
Runs parallel from Week 16 onwards
PM interviews have exactly 4 question types. Know all 4 cold.The behavioral questions are where Samarth wins — the IDH platform build, the HDFC stakeholder work, the Chetna Foundation scope expansion from 1 to 3 projects. These are real PM decisions, not hypotheticals.

The 4 question types

Type 1Product Design / Sense. Framework: clarify scope → user segments → pain points → ideate → prioritise by impact → define metrics. Practice 2 questions per week out loud.
Type 2Metrics / Analytical. "Sessions dropped 20% — walk me through your thinking." Framework: segment → hypotheses → validation → fix. Follow with SQL if asked.
Type 3Estimation. Structure: anchor on known data → build up from components → sanity check. 1 estimation question per day, under 5 minutes.
Type 4Behavioral. STAR format. Your 6 stories: IDH requirements ambiguity, HDFC national convention, Chetna scope expansion, UNM field research, SettleMed UiPath automation, leading a team of 6. Write these before your first interview.
